# Plan: list content and page meta in `data/` (MY-187)

Goal: no list content is hard-coded in a section partial, the header renders the navigation from
data, and `context(pagePath)` hands the templates the current `page` instead of one `is*` flag per
page. Observable behavior does not change (no spec): the built pages stay the same apart from
whitespace and the `<title>`.

## Data (`src/data/`)

- `products.js` → `products`: `{ individuals: [...], businesses: [...] }`, each card `{ icon, title, description }`.
- `values.js` → `values`: `{ title, text }`.
- `hero-transactions.js` → `heroTransactions`: `{ title, name, amount }`; the icon stays in the partial (decor).
- `navigation.js` → `navigation`: `{ label, href, key }`; `key` is the page's `navKey`.
- `pages.js` → `pages`: one entry per page file name (`index`, `about`, `careers`, `security`) with
  `title`, `description` and `navKey`.

## Templates and wiring

- `products.html`: the two panels loop over `products.individuals` / `products.businesses` through
  `components/product-card`; the divider between cards is `{{#unless @last}}`. The toggle, ids and `data-toggle-*`
  hooks stay as they are.
- `values.html`, `hero.html`: `{{#each}}` over `values` / `heroTransactions`.
- `header.html`: `{{#each navigation}}`; `aria-current="{{#if (eq key ../page.navKey)}}page{{else}}false{{/if}}"`,
  the condition stays inside the value.
- `vite.config.js`: `context(pagePath)` returns `page: pages[name]` and the data constants, without the
  `is*` flags; `helpers: { eq }` on the plugin. The four pages' `<title>` is `{{page.title}}`. `description` is
  stored but not rendered: the meta set is MY-202. The 404 plugin and `rollupOptions.input` are untouched.

## Docs

`ai/rules/html.md` (the `page` context and the `eq` helper replace the flags), `ai/rules/architecture.md` and
