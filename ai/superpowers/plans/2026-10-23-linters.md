# Plan: ESLint, Stylelint, Husky and lint-staged (MY-182)

Goal: a lint run for JavaScript and CSS, a pre-commit hook that checks and formats what is staged,
and a `format:check` that passes on a Windows CRLF checkout and on Linux. No spec: no behavior or
look changes. The author's answers (2026-10-23) are final: Stylelint is in, line endings are
`endOfLine: "auto"` without `.gitattributes`, the header attribute moves into its value.

## Dependencies

Dev dependencies, npm only: `eslint`, `@eslint/js`, `globals`, `eslint-config-prettier`, `stylelint`,
`stylelint-config-standard`, `husky`, `lint-staged`. No plugins, no custom rules.

## ESLint

`eslint.config.js`, flat config: `@eslint/js` recommended, `globals.browser` for `src/`,
`globals.node` for `vite.config.js`, `eslint-config-prettier` last. `dist/` and `.claude/` (worktrees) are ignored. Whatever the
recommended set reports in the current code is fixed without a behavior change.

## Stylelint

`.stylelintrc.json` extends `stylelint-config-standard` (it already understands native nesting). Added:

- `selector-class-pattern` for BEM, `block__element--modifier`, kebab-case words: elements and
  modifiers are optional, nothing nests deeper than one `__`.
- `color-no-hex`, with an override that switches it off for `styles/general/variables.css`; hex is
  the only colour form the standard config can forbid cheaply, `rgb(` and `hsl(` outside the tokens
  stay a review matter (`ai/rules/css.md`).
- `ignoreFiles` for `dist/`.

Found and fixed: the `@import` lines use `url()`; pseudo-elements use two colons; the vendor-prefixed
`box-sizing` lines are gone; the hero colours come from tokens (`--green-10` is new, the gradient
uses `transparent` and `--grey-10`); an empty `.hero__change` rule is removed; `.case-item__icons` and
`.header__menu-line` move before the more specific rules that override them. The built CSS differs
only in the hero colours.

Anything standard reports that would change the look or rewrite a rule (`declaration-block-no-redundant-longhand-properties`,
`shorthand-property-no-redundant-values`, a `rgba` to `rgb` notation) is fixed mechanically with
`stylelint --fix` where it is safe; a rule whose fix would change the cascade is turned off by name
with the reason in the report, not rewritten. CSS edits stay minimal and mechanical: MY-181 edits a
few `url()` lines in the same files, and its branch rebases after this one.

## Prettier

- `.prettierrc`: `endOfLine: "auto"`. Prettier keeps each file's existing endings, so a CRLF
  checkout and an LF checkout both pass; no `.gitattributes`. A decision record.
- The header: every nav link is written as `aria-current="{{#if isHome}}page{{else}}false{{/if}}"`,
  the attribute always present and the condition only in the value, so Prettier parses the tag and
  no `.prettierignore` entry is needed. CSS keeps selecting `[aria-current='page']`; built pages are
  checked to have one `page` and three `false`.
- Handlebars in pages: `htmlWhitespaceSensitivity` (`css`, `strict`, `ignore`) was tried on the
  pages and none puts one `{{> partial }}` per line: Prettier treats the calls as text and reflows
  them, sometimes inside the mustache. The setting is left at its default, Prettier's output is kept
  and the result is reported; a `prettier-ignore` comment is out (no comments in code).

## Husky and lint-staged

- `prepare: husky`; `.husky/pre-commit` runs `npx lint-staged`.
- `.lintstagedrc.json`: `*.js` → `eslint --fix`, `prettier --write`; `*.css` → `stylelint --fix`,
  `prettier --write`; `*.{html,json,md,yml}` → `prettier --write`.
