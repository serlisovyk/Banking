# Plan: CI on GitHub Actions with size-limit (MY-183)

Goal: GitHub runs the same checks as the local gate after every push and pull request to `main`, so
a commit that skipped the pre-commit hook (`--no-verify`, a web edit, a bot's pull request) still
cannot land a lint error, an unformatted file, a broken build or a heavier bundle unnoticed. No
spec: nothing the site does or shows changes.

## Workflow

One file, `.github/workflows/ci.yml`, one job on `ubuntu-latest`:

- Triggers: `push` and `pull_request` on `main`.
- `actions/checkout@v4`, `actions/setup-node@v4` with `node-version: lts/*` and `cache: npm`.
  `engines` is a range (`^20.19.0 || >=22.12.0`), which `setup-node` would resolve to the newest
  matching Node, not a stable one; `size-limit` itself needs 22.19 or newer, so the current LTS
  satisfies both.
- `npm ci`, then `npm run lint`, `npm run lint:css`, `npm run format:check`, `npm run build`,
  `npm run size`, each its own step so a failure names the check.
- `npm ci` runs `prepare` (`husky`). Husky 9 does nothing outside a git work tree with hooks to
  install; Actions checks out a work tree, so it installs the hook harmlessly. Confirmed by the
  run.
- `format:check` passes on Linux because of `endOfLine: "auto"` (`line-endings-auto`).
- Action majors are pinned (`@v4`); no comments, no extra jobs, matrix, caching beyond npm, or
  concurrency settings.

## size-limit

Dev dependencies: `size-limit` and `@size-limit/file` only. The `file` plugin measures built files
as they are, which is all we need: no bundler preset (`webpack`, `esbuild`), so no second build.
Script `size`: `size-limit`, run after `npm run build`. Config `.size-limit.json` (comments are not
allowed in JSON; the reasoning goes into the decision record).

Numbers from a build of `main` (gzip for text, raw for images, which are already compressed):

| Entry                        | Path                        | Now     | Limit  |
| ---------------------------- | --------------------------- | ------- | ------ |
| JavaScript                   | `dist/assets/*.js`          | 1.3 kB  | 3 kB   |
| CSS                          | `dist/assets/*.css`         | 3.4 kB  | 5 kB   |
| Raster images (decor, photo) | `dist/assets/*.{avif,webp}` | 91.5 kB | 120 kB |

The margin is roughly a third to a half over today: enough for the CSS and JS refactors that run
next and for a section or two, tight enough that an unoptimised photo or a per-dot vector decor
(`light-decor-raster`) fails the check. The images are one total rather than a first-screen
subset: the decor and the Careers photo are the only rasters, and a total does not need updating
when a section moves its image. The font and SVG icons are not limited: one self-hosted font file
that `assets-performance` already fences, and icons of a few hundred bytes.

## Verification

- Locally: `npm run lint`, `npm run lint:css`, `npm run format:check`, `npm run build`,
  `npm run size`; a deliberately lowered limit makes `npm run size` exit non-zero, then it is
  restored.
- The branch `my-183-ci` is pushed (not `main`); the Actions run on it is read through the public
  API and must be green. A failing step was already shown locally for `size`; lint and format are
  the same commands the hook runs.
