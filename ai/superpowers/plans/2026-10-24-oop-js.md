# Plan: JavaScript in OOP style (MY-186)

Goal: every module in `src/scripts/` becomes a class, per `ai/rules/oop.md` and the record
`ai/decisions/2026-10-23-oop-javascript.md`. No spec: behavior and ARIA stay 1:1 with today. No
open questions.

## Structure

- `main.js` — a table of `{ selector, Controller }`; for each root found it creates the controller and
  calls `start()`. No `DOMContentLoaded`, no logic, a section missing from the page is skipped.
- `constants.js` — named exports, lookups under `Object.freeze`: the two media queries
  (`MOBILE_MEDIA_QUERY` `(width < 768px)`, `TABLET_MEDIA_QUERY` `(width < 1024px)`, the structural
  breakpoints of the CSS), key names (`KEYS`), the menu and FAQ button texts, the state classes
  (`is-open`, `button--empty`, `features__button--active`, `features__items--active`,
  `questions__more--expanded`).
- `components/` — reusable, find their children by generic `data-*` hooks inside `root`, take
  everything section-specific (classes, texts, queries) from `options`:
  - `Tabs` — `[role="tablist"]`, `data-tab`, `data-tab-panel`; roving `tabindex`, `aria-selected`,
    arrows by orientation, `Home` / `End`, `aria-orientation` from a media query (`select`).
  - `Toggle` — `data-toggle-button`, `data-toggle-panel`; `aria-pressed`, `hidden` on the panels,
    an optional class on the inactive buttons (`select`). Products now, Testimonials later.
  - `Disclosure` — `data-disclosure-trigger`, `data-disclosure-region`, `data-disclosure-label`;
    `aria-expanded`, `inert`, an expanded class, the height as a custom property recalculated on
    open and on `resize`, an optional pair of labels (`open`, `close`, `toggle`, `isOpen`).
- `controllers/` — `HeaderMenuController` (the menu itself: `aria-expanded`, `aria-label`, `inert`
  below 768px, `Escape` returns focus to the button, a followed link or a breakpoint change
  closes it), `ProductsController` (`Toggle`), `FeaturesController` (`Tabs`), `FaqController`
  (`Disclosure`). Each takes its `root` and an optional `options` that overrides the constants.
  Several instances of one section work: nothing is found from `document` outside `main.js`, and
  the `Escape` listener of a menu only reacts to its own open menu.

## Markup

Hooks are `data-*`, so the partials change by attributes only: a root hook on each section
(`data-header`, `data-products`, `data-features`, `data-questions`), the header button and nav
(`data-header-menu-toggle`, `data-header-nav`; the `id`s stay for `aria-controls`), the component
hooks above in place of `data-products-*`, `data-features-*`, `data-questions-toggle*`, and
`data-disclosure-region` on the extra questions. No class, text or ARIA changes. Only the
attributes move, so a merge with MY-185 (partials and styles) is a few lines.

## Left out

`.size-limit.json` and `npm run size` do not exist on this branch (they come with MY-183), so the
JS limit is revisited there. The `id="questions-more"` / `aria-controls` pair stays as it is; it
becomes per-instance with the shared FAQ partial (MY-192).

## Verification

`npm run lint`, `npm run format:check`, `npm run build`; `npm run preview -- --port 4186` and a
`main` build side by side: the burger (mouse, keyboard, `Escape`, a link, resizing across 768),
Products, Features tabs (arrows, `Home` / `End` at 1920 and at 390 where the orientation flips), the
FAQ expand and collapse with a resize, on every page that has them; no console errors; the
`aria-*`, `hidden` and `inert` states compared with `main`. Servers are stopped by PID.
