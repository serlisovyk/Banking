# Linters: ESLint, Stylelint, Husky and lint-staged

Date: 2026-10-23 · Status: accepted

## Context

Prettier was the only automatic check, and only when someone ran it. Unused variables, accidental
globals, mistyped CSS properties and hard-coded colours were caught by nothing.

## Decision

- ESLint, flat config: `@eslint/js` recommended, browser globals for `src/`, node globals for the
  configs, `eslint-config-prettier` last. No custom rules, no plugins.
- Stylelint: `stylelint-config-standard` (it understands native nesting), `selector-class-pattern`
  for BEM (`block__element--modifier`), and `color-no-hex` everywhere but `variables.css`.
- Husky runs lint-staged before each commit: ESLint and Stylelint `--fix`, then Prettier, on the
  staged files; a commit that still has an error is refused. The hook is never bypassed.
- Scripts: `lint`, `lint:fix`, `lint:css`, `lint:css:fix`; they join the checks in `AGENTS.md`.
- A nav link's `aria-current` is always present, with the condition in its value, so Prettier parses
  the partial and no `.prettierignore` entry is needed.

## Consequences

- A new rule, plugin or a rule turned off is a new dated record, not a quiet config edit.
- `rgb(` and `hsl(` outside `variables.css` are still a review matter: no standard rule forbids them
  without also forbidding colour functions inside the tokens.
- Prettier reflows `{{> partial }}` calls on a page as text (`htmlWhitespaceSensitivity` does not
  change it); its output is kept rather than ignoring the pages.
- Rejected: a Handlebars plugin for Prettier or a `prettier-ignore` comment (a dependency or a
  comment in code for formatting only).
