# Repo map

Navigation only: where things live and who owns what. How it works is in the code, why in `ai/decisions/`.

## Repo

- `src/` — every source, and Vite's `root`. The pages sit at its top: `index.html` (`/`), `about.html`, `careers.html`,
  `security.html`. Each lists the partials it uses.
- `src/partials/sections/<page>/` — partials of a page section (`shared/` for those used by several pages);
  `src/partials/components/` — partials of a repeated element (a card, a list item). A partial is called by its path.
- `src/data/` — the data the partials render; each file exports one constant, wired in through `context` in `vite.config.js`.
- `src/styles/` — all CSS (below). `src/scripts/` — all JavaScript (below).
- `src/assets/` — `fonts/`, `images/`: referenced as `/assets/…`, bundled and hashed (below).
- `public/` — files that need a fixed URL, served as they are; not created until one exists.
- `vite.config.js` — Vite (`root: 'src'`, output `dist/` at the repo root) with `vite-plugin-handlebars`: the `partials`
  folder and `context(pagePath)`, which sets the `isHome`, `isAbout`, `isCareers`, `isSecurity` flags and passes the
  `data/` constants. The pages are listed in `build.rollupOptions.input`.
- `package.json` — scripts `dev`, `build`, `preview`, `format`, `format:check`; `package-lock.json` — the lockfile
  (npm, decision `npm-package-manager`). `.prettierrc`, `.prettierignore` — Prettier. License: MIT, declared in `package.json` only (decision `license-in-package-json`).
- `AGENTS.md` — the entry point for agents; `CLAUDE.md` points to it.
- `ai/` — agent docs: this map, `workflow.md`, `rules/`, `skills/`, `decisions/`, `prompts/`,
  `linear-task-template.md`, and the archive `superpowers/`.
- Build plugins, in `vite.config.js`, `build` only: `vite-plugin-image-optimizer` (sharp, SVGO) and an HTML minifier
  (`html-minifier-terser`). CSS has no setup: Vite's own lightningcss minify and target (decision `build-pipeline`).
- `dist/` — generated by `npm run build`; never edited.
- `.claude/worktrees/` — one git worktree per task when tasks run in parallel; ignored by git.

## Pages

- `index.html` — `shared/header`, `home/hero`, `home/products`, `home/cases`, `home/features`, `home/questions`.
- `careers.html` — `shared/header`, `careers/careers-hero`, `careers/values`.
- `about.html`, `security.html` — only `shared/header` so far.
- Every page links `/styles/style.css` and `/scripts/main.js` in `<head>`.

## Partials (`src/partials/`)

- `sections/shared/header` — logo, navigation (`aria-current` from the page flags), the mobile menu button.
- `sections/home/hero`, `sections/careers/careers-hero` — the first screens of home and Careers.
- `sections/home/products` — the audience switch (For Individuals / For Businesses) and two panels of `product-card`.
- `sections/home/cases` — Use Cases: `caseItems` as `case-item`.
- `sections/home/features` — category tabs: `featureGroups` as tabs, panels of `feature-item`.
- `sections/home/questions` — the FAQ: `questionGroups` as `question-item`, the rest under an expander.
- `sections/careers/values` — Our Values on Careers.
- `components/` — `product-card`, `case-item`, `feature-item`, `question-item`: data comes as hash parameters or from `each`.

## Data (`src/data/`)

- `case-items.js` → `caseItems`, `feature-groups.js` → `featureGroups`, `question-items.js` → `questionGroups`.

## Styles (`src/styles/`)

- `style.css` — imports the files below in order: `general`, `ui`, `components`, `sections`.
- `general/` — `reset.css`, `fonts.css` (`@font-face`), `variables.css` (every token), `main.css` (`body`, `.container`, `.section`).
- `ui/` — the shared elements: `button.css`, `headings.css`.
- `components/`, `sections/` — one stylesheet per partial of the same name.

## Scripts (`src/scripts/`)

- `main.js` — imports the section modules below (the only entry; the pages load it).
- `header-menu.js` — the mobile menu: `aria-expanded`, `inert`, `Escape`, close on a link.
- `products.js` — the audience switch: `aria-pressed`, `hidden` on the panels.
- `features.js` — the ARIA tabs: arrows, `Home`/`End`, orientation by width.
- `questions.js` — the FAQ expander: `aria-expanded`, `inert`, the height as a custom property.
- These are still procedural modules; the target layout is classes in `scripts/controllers/` and `scripts/components/`
  (`ai/rules/oop.md`), which MY-186 migrates to.

## Assets (`src/assets/`)

- `fonts/` — the self-hosted Lexend `woff2`. `images/` — `logo.svg`, the hero backgrounds, `icons/`, `decor/`, `flags/`.
- Referenced by the root path (`/assets/images/…`) in HTML, `data/` and CSS; the build emits each once, hashed.

## Where is the recipe

- A page section or a repeated element: `ai/skills/section.md`. Reviewing a diff: `ai/skills/review.md`.
- Colours, type, spacing, components and the sections of each page, as designed: `ai/design-system.md`.
- What must hold: `ai/rules/`. Why it is so: `ai/decisions/` (index in its `README.md`).

## Deployment

Live at <https://banking-coral-three.vercel.app> on Vercel through its Git integration: `main` is production, other
branches get previews (decision `vercel-deploy`).

## Not in this project

- No UI framework, TypeScript, CSS preprocessor or backend: decision `vanilla-js-vite-handlebars`.
- No automated tests: decision `no-automated-tests`. No pull requests: decision `local-merge-without-pr`.
- No Login or Sign Up pages: decision `four-pages-no-auth`. No external currency API: `ai/rules/scope.md`.
- No linter, pre-commit hook or CI yet: they are in scope, not built.
